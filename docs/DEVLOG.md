### 故障档案

**#1 客车穿透地面（自由落体）** — 现象：客车出生后 3 s 速度 ≈ 自由落体（126 km/h），穿过路面与地面。定位过程：最小复现（1000 kg 四轮）正常 → 质量改 12000 kg 复现穿透 → 读 Godot 源码 `vehicle_body_3d.cpp`。根因（复合）：
- 悬挂力公式为 `刚度 × 压缩量 × 车体质量`，再被 `suspension_max_force` 独立钳制（不乘质量）——大质量车辆极易悬挂"塌陷"；
- 原悬挂几何（连接点 0.75 = 静止长度 0.25 + 轮半径 0.5）射线检测余量为零，车身必须沉入地面才有第一帧接触；
- 原阻尼 0.85/0.9 在质量缩放下严重欠阻尼（ζ≈0.16），接触后弹跳失控、姿态发散沉底；
- 车体无碰撞形状，悬挂一旦失效即永久坠落。
修复：连接点降至 0.65 + 静止长度 0.35（余量 0.2 m）+ 行程 5.0 + 阻尼 1.2/1.5（近临界）+ **新增底盘 BoxShape 碰撞兜底**。修复后 6 轮持续接触、0.1 m 幅内稳定收敛。

**#2 客车倒着开** — 现象：AC5 中客车头朝站点（fwd_dot=1.0）却越开越远。根因：Godot VehicleWheel 的前向摩擦轴由"车轴×接触法线"决定，本车布局下为 +Z，而车头建模在 -Z，正 `engine_force` 推向车尾。修复：控制器中驱动力取负并注释依据；R 挡同步反向。附带发现：AC3 翻车（直立度 -0.59）为高速制动前俯 + 高重心 + 原制动力过大（抱死减速度 4g）联合所致——制动力 5500→800、重心 1.15→0.95、底盘碰撞箱抬高后解决。

**#3 "无输出崩溃"实为超时挂起** — 现象：某几轮测试进程零输出、exit 1 SIGTERM。根因：测试协程中调用了 4.7.2 不存在的方法（`get_suspension_force`）→ SCRIPT ERROR 中断协程 → 永不调用 quit() → headless 死循环到超时。教训：测试脚本必须使用看门狗式退出（`_physics_process` 帧计数强制 quit），或只用确认存在的 API。

**#4 极速均衡 ~58.8 km/h** — 现象：无论提升调速器目标（90→110）或驱动力（+33%），加速均衡点稳定在 58.8 km/h。已排除：线性阻尼（显式置零无效）、调速器、滚动阻力。疑似 Godot VehicleWheel 前向滚动摩擦的速度匹配机制限制。按故障处理纪律（3 次迭代即停）登记为已知限制，v0.2.0 调查。AC3 制动判据余量 8.4 倍，实质达标（详见 test_report 已知限制①）。

## 2026-11-14 — 驾驶手感调参与故障 #5/#6（v0.1.1）

用户试驾反馈：转向轻点过灵（近侧翻）→ 二轮修正后过肉（"按了基本没转"）；刹车轻点几乎刹停；R 挡倒车数秒后自动跳回 D；倒挡视角提示不明显。

**手感改造（三轮迭代，全部经 feel_check 量化回归）**：
- 转向架构重设计：线性随速限角 → **侧向加速度预算**（δ_max = atan(a·L/v²)，a=10 m/s²）。物理依据：客车侧翻阈值 = g·半轮距/重心高 = 15.7 m/s²（重心 0.95→0.75 m、轮距 2.24→2.40 m 配套调整），任何车速满舵侧向加速度恒定且留 36% 余量。首轮线性限角方案（min 14°@70 km/h）在 53 km/h 满舵实测翻车（直立度 0.006）被否决。
- 打轮/回正速率 120°/s / 160°/s（首轮 40°/s 用户反馈过肉）。
- 刹车：力 800→250 N/轮 + **踏板渐变**（踩下 1.5/s、释放 6/s），键盘阶跃→渐进行程；轻点掉速 11.5→5.5 km/h。
- 倒挡反馈：HUD 挡位/速度红色 + 顶部横幅 + **车尾射线倒车雷达**（12 m）；高速误挂 R 拦截。
- feel_check.tscn 保留为常驻手感回归（轻点刹车/转向、满舵防翻、R 持续倒车、锁挡五组量化断言）。

**故障档案（续）**

**#5 R 挡倒车数秒后自动跳回 D** — 现象：挂 R 倒车，速度超过 8 km/h 后挡位自动变 D。根因链条：倒挡误操作保护用了**绝对速度**（`get_speed_kmh()`）——纯倒车速度升高被误判为"高速行驶中挂 R"→ 保护弹回 N → 空挡踩油门自动回 D 逻辑接力挂入 D。修复：改用**带符号前向速度**（`get_signed_forward_speed_kmh()`），仅"仍在向前冲"（正值 >8）时锁挡，倒车（负值）永不触发。回归：R 挡持续倒车 6 s 峰值 14.6 km/h 全程保持 R，停车后仍为 R。

**#6 自动驾驶趴窝（外部控制油门失效）** — 现象：`--auto` 模式客车挪动 1.5 m 后停死，AUTO_STOP 不再出现（v0.1.0 曾 176.5 s 通过）。根因：本轮踏板渐变重构时，外部控制分支只给 `_throttle_pedal` 赋值，未回赋局部变量 `throttle`/`brake_in`，外部油门输出恒 0。headless AC 套件走 Input 路径不受影响（6/6 照常通过）——**自动化测试没覆盖外部控制路径，教训：改公共输入管线时两条路径都要回归**。修复后自动驾驶 175.1 s 完整跑完并停至站前 3.9 m。autopilot 增加 5 s 周期过程日志（AUTO_DBG）便于此类定位。

### #10 AC5 间歇性失败（20 m 挡停）——清场逻辑把车"清"进了进站通道

- 现象：本轮跑 AC 套件，AC5 间歇失败（19.5/18.1/20.8 m 挡停，偶发通过 2.0 m）。stash 验证与本次视角改动无关（v0.1.4 基线同样失败）——v0.1.4 当天只跑了 feel_check 未跑全套 AC，漏网。
- 诊断：AC5 失败时打印附近交通车 → 一辆**同向货车 s=2462 横在客车（2453）与站点（2470）之间**（冻结不挪窝）。
- 根因（两个叠加 bug）：
  1. `relocate_conflicts` 把同向冲突车推到"客车前方 300 m"，但 `_find_clear_s` 钳制到 `total-12=2458`——AC5 传送点（2350）恰好落在某同向车初始槽位 ±30 m 内时，该车被"清场"**清进了终点进站通道**，永久挡住蠕行路径。
  2. `_spawn_all` 用 `entries.shuffle()` 走**全局随机**（非播种 `_rng`）→ 每次进程启动布局不同 → 测试间歇性、不可复现（同代码三次运行 19.5/2.0/18.1 m）。
- 修复：① 同向车清场目标位加**终点保护**（落在路线末端 160 m 内改推客车后方 300 m）；② `relocate_conflicts` 新增 `clear_ahead` 参数（清空前方同向车），AC5 传送显式清空 140 m 进站通道；③ 洗牌改为播种 `_rng` 的 Fisher-Yates，恢复确定性。
- 验证：AC 套件连跑 3 次全部 6/6 通过（AC5 稳定 2.0 m，蠕行 0 段）。

**回归结果**：AC 6/6 ×3（确定性）；feel_check 14/14（FEEL_CAB_CAM 新增）；GUI 启动 + AC7 16.67 ms ✅；GUI 自动驾驶 334.1 s 完整闭环（真实 TTS、红灯等待）。
